# 규정 데이터 모델 및 수집 체크리스트

## 목적

근거문서를 단순 문장 검색용으로만 저장하지 않고, 적용대상·조건·예외·계산효과를 추적 가능한 규칙으로 변환한다. AI는 설명을 생성할 수 있지만 급여액과 자격 판단은 승인된 규칙 엔진이 담당한다.

## 핵심 엔터티

### SourceDocument

- `id`, `title`, `authority`, `documentType`
- `publishedAt`, `effectiveFrom`, `effectiveTo`
- `correctionAsOf`, `version`, `supersedesId`
- `officialUrl`, `localFile`, `sha256`, `status`
- `priority`, `accessLevel`, `allowedUses`

### Rule

- `id`, `sourceDocumentId`, `page`, `sectionPath`, `verbatimLocator`
- `topic`: 복무·기본급·수당·공제·복지·보험·퇴직 등
- `summary`, `conditions`, `exceptions`, `requiredDocuments`
- `effectiveFrom`, `effectiveTo`, `reviewStatus`, `reviewedBy`
- `conflictGroup`, `supersedesRuleId`

### Applicability

- `employmentPayType`: 월급제·일급제·시급제
- `employmentTermType`: 무기계약·기간제·단시간·초단시간
- `occupationId`, `institutionType`, `workScheduleType`
- `weeklyContractHours`, `dailyContractHours`, `annualWorkDays`
- `vacationNonWorking`, `qualification`, `hireDate`, `servicePeriod`

직종명으로 급여형태나 방학 중 비근무 여부를 자동 확정하지 않는다.

### Impact

- `ruleId`, `impactType`
- 급여·연차·수당·퇴직금·복지포인트·4대보험·시스템처리·제출서류
- `effect`: 발생·감액·중지·변경없음·검토필요
- `formulaId`, `explanation`, `confidence`

### Formula

- `id`, `name`, `inputs`, `expression`, `roundingRule`
- `sourceRuleIds`, `effectiveFrom`, `effectiveTo`
- `testCaseIds`, `approvalStatus`

Formula에는 AI가 생성한 자유문장을 실행하지 않는다. 사람이 검토한 결정적 계산식만 사용한다.

### TestCase

- `id`, `occupation`, `inputSnapshot`, `expectedResult`
- `sourceRuleIds`, `calculatedAt`, `reviewedBy`, `status`
- 경계값·월중 입퇴사·방학·휴직·근로시간 변경 사례 포함

## 1차 검증 유형

1. 교육실무사 — 월급제·상시근무
2. 영양사 — 월급제·상시근무·자격 및 직종수당
3. 특수교육실무사 — 연간근무일수제
4. 조리사 — 급식 직종·자격수당
5. 조리실무사 — 급식 직종·방학 영향
6. 시급제 단시간 근로자 — 생활임금·주휴·근로시간

각 유형은 직종을 고정 규칙으로 삼지 않고 대표 테스트 프로필로만 사용한다.

## 조항 추출 체크리스트

- [ ] 원문 문서 ID와 정확한 쪽을 기록했다.
- [ ] 장·절·항목명을 기록했다.
- [ ] 적용 대상과 제외 대상을 분리했다.
- [ ] 시행일·회계연도·학년도를 구분했다.
- [ ] 상시근무·방학 중 비근무·연간근무일수를 분리했다.
- [ ] 월급제·일급제·시급제 조건을 분리했다.
- [ ] 기본급·수당·공제·복지 항목을 분리했다.
- [ ] 계산식의 절사·반올림·일할 계산 기준을 기록했다.
- [ ] 휴가·휴직·결근·입퇴사·근로시간 변경 영향을 기록했다.
- [ ] 제출서류와 담당자 처리 절차를 기록했다.
- [ ] 상위 근거와 예외 규정을 연결했다.
- [ ] 충돌 가능성이 있으면 `conflictGroup`을 지정했다.
- [ ] 최소 2인이 원문과 구조화 결과를 대조했다.

## 서비스 안전 게이트

1. `catalog_only`: 목록에만 표시, 답변 근거 사용 금지
2. `retrieval`: 원문 검색과 인용 가능, 계산 금지
3. `rule_extracted`: 구조화 완료, 검토 전
4. `approved_for_answer`: 답변 근거 사용 가능
5. `approved_for_calculation`: 계산식과 테스트까지 승인

## 바로 이어서 할 작업

1. 복무지침과 임금지침의 목차·쪽 번호를 추출한다.
2. 6개 검증 유형과 연관된 장·절을 우선 표시한다.
3. 복무 항목 하나를 선택해 `Rule → Applicability → Impact` 샘플을 완성한다.
4. 샘플을 사용자와 검토한 뒤 나머지 항목을 같은 방식으로 확장한다.

첫 샘플 항목은 `병가`를 추천한다. 근무형태별 차이, 급여 영향, 진단서, 연차·휴직 연계가 있어 전체 데이터 모델을 검증하기 좋다.
